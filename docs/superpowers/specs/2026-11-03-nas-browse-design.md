# 공용 NAS 하드를 Drive 앱에서 탐색하기

> 상태: 구현했다. 실제 하드로 켜기 전에 아래 "실제로 켜기 전에 확인할 것"을 확인한다. 구현 계획: [2026-11-04-nas-browse.md](../plans/2026-11-04-nas-browse.md), 수동 테스트 목록: [2026-11-04-nas-browse-test-checklist.md](../plans/2026-11-04-nas-browse-test-checklist.md)

## 왜 만드나

디자인팀이 예전에 쓰던 공용 NAS 하드(4TB NTFS, 약 3TB 사용 중)에 옛 자료가 남아 있다. 디자이너 PC에는 모두 Drive 앱이 깔려 있으므로, 앱 안에서 이 하드를 탐색하고 검색하고 내려받을 수 있게 한다.

Seafile은 항상 켜 둔 Windows PC의 Hyper-V Ubuntu에서 Dokploy로 돌고 있고, 쓰는 디스크는 1TB다. 3TB를 Seafile로 옮기기에는 디스크가 부족하고, Seafile은 바깥 디스크를 그 자리에서 보여 주지 못한다. 그래서 하드의 파일은 하드에 그대로 둔다.

## 최종 모습 (사용자 결정)

- **설치**: 하드를 Seafile 서버 PC(항상 켜 둔 Windows PC)에 연결한다.
- **열어 두기**: 관리자가 Seafile 사용자 "디자인나스"를 하나 만든다. 그 PC에 Drive 앱을 깔고 디자인나스로 로그인한 뒤 하드 폴더를 "NAS로 열기"로 열어 둔다.
- **쓰기**: 디자이너는 자기 PC의 Drive 앱 사이드바에 떠 있는 **"디자인나스"**에서 탐색하고, 이름으로 검색하고, 내려받는다. 이름은 제공 PC가 로그인한 계정 이름을 그대로 쓴다.
- **내려받기만** 한다. 업로드, 이름 변경, 삭제는 없다.
- **권한은 하나**: 사무실 네트워크 안에서 Drive 앱을 쓰는 사람이면 누구나 전체를 본다(디자이너 앱은 자기와 같은 Seafile 서버 주소를 알리는 제공 PC만 찾으므로, 같은 서버에 로그인한 앱이 대상이다). 로그인 확인은 하지 않는다.
- **썸네일은 만들지 않는다**: NAS 항목은 확장자 아이콘만 보여 준다.

## 하지 않는 것

- 업로드·수정·삭제(하드는 읽기만 한다)
- 썸네일·미리보기 생성(원본을 통째로 읽어야 해서 느림)
- 공유 링크, 휴지통, 파일 히스토리(Seafile 기능이라 NAS에는 없음)
- 폴더별 권한
- 웹 버전 지원. 웹에서는 숨긴다.
- 사무실 밖에서의 접근
- 내용 검색. 이름 검색만 한다.

## 구조 (빌더 판단)

```
[Seafile 서버 PC · Drive 앱 (디자인나스 로그인)]
  하드 폴더 ── NAS 제공 (Rust): 목록·색인·파일 보내기
             └─ 사무실 네트워크에 "디자인나스" 알림 (mDNS)
                       │ 암호화 연결(TLS)
[디자이너 PC · Drive 앱]
  사이드바 "디자인나스" ── NasProvider ── 제공 PC에 목록·내려받기 요청
  검색 ── 제공 PC에서 색인을 받아 기존 이름 검색으로 필터
```

디자이너 PC가 하드에 직접 접속하지 않고, 제공 PC의 Drive 앱을 거친다. 그래서 디자이너 PC에는 SMB 공유 설정이나 계정이 필요 없다. 하드가 제공 PC에 직접 붙어 있으므로 제공 PC도 로컬 디스크로 읽는다.

### 1. 제공 PC: NAS로 열기

- 설정에 "NAS로 열기"를 두고, 하드 폴더를 고른다. 이 PC에 저장한다.
- 열어 두면 Rust가 사무실 네트워크에서 요청을 받는다. **바로 보내기**의 기반을 재사용한다.
  - 기기 찾기: mDNS(`nearby.rs`). 서비스 정보에 서버 주소, 이름(로그인한 계정 이름, 예: "디자인나스"), 인증서 지문을 담는다.
  - 암호화: 실행마다 새로 만드는 자체 서명 인증서와 지문 고정(`tls.rs`).
- 요청 세 가지만 받는다: 폴더 한 단계 목록, 검색 색인, 파일 내려받기(이어 받기를 위해 범위 지정).
- **경로 제한**: 고른 하드 폴더 밖은 읽지 못한다. `..`, 링크, 절대 경로로 빠져나가지 못하게 막는다(신뢰 경계).
- 앱 창을 닫아도 트레이에서 계속 돌아야 한다. 열 때 자동 실행과 트레이 실행이 꺼져 있으면 켜도록 안내한다(폴더 동기화와 같은 안내).
- 로그아웃하거나 "닫기"를 누르면 제공을 멈춘다. 폴더를 열어 둔 적이 있으면 다시 로그인했을 때 자동으로 다시 연다.

### 2. 접근 확인

- 인증은 하지 않는다(사용자 결정). 사무실 네트워크 안에서 Drive 앱을 쓰는 사람이면 누구나 읽기 전용으로 볼 수 있다.
- 디자이너 앱은 Seafile 토큰을 어떤 기기에도 보내지 않는다. `_udrive-nas`는 같은 네트워크의 아무 기기나 알릴 수 있어서, 토큰을 보내면 가짜 기기가 토큰을 받아 가기 때문이다.
- 디자이너 앱은 자기와 같은 Seafile 서버 주소를 알리는 제공 PC만 목록에 올린다. 다른 서버의 제공 PC는 사이드바에 보이지 않는다.
- 제공 쪽은 요청을 읽기 전용(목록·색인·내려받기)으로만 받고, 고른 폴더 밖은 읽지 못한다.

### 3. 디자이너 앱: 탐색·내려받기

- `StorageProvider`([src/storage/StorageProvider.ts](../../../src/storage/StorageProvider.ts))를 구현하는 `NasProvider`를 만든다. 사이드바에서는 읽기 전용 라이브러리 하나("디자인나스", `readOnly: true`)로 보인다.
- 미리보기, 썸네일, 공유, 바로 보내기, 즐겨찾기, 이름 변경, 삭제, 업로드는 NAS 라이브러리에서 숨긴다.
- NAS 라이브러리 목록은 기기를 찾거나 잃을 때와 5분마다 새로 고친다.
- 제공 PC를 찾지 못하면 "디자인나스에 연결할 수 없습니다. 서버 PC의 Drive 앱이 켜져 있는지 확인하세요"를 보여 준다.
- 내려받기는 기존 다운로드 패널을 쓴다. 큰 PSD도 받아야 하므로 조각으로 받는다.

### 4. 검색

- 제공 앱이 하드 전체를 훑어 색인(`Entry` 모양: `name`, `type`, `size`, `mtime`, `path`)을 만든다. 열 때 한 번 만들고, 변경 감시(폴더 동기화의 `notify`)로 갱신한다. 감시가 빠지는 경우를 위해 하루 한 번 다시 훑는다.
- 디자이너 앱은 색인을 받아 [useSearchIndex.ts](../../../src/features/search/useSearchIndex.ts)의 기존 이름 검색에 넣는다. 색인 버전(만든 시각)이 같으면 다시 받지 않는다.
- 파일이 수십만 개면 localStorage(약 5MB)에 들어가지 않는다. 캐시는 메모리에만 두거나 앱 데이터 폴더의 파일로 저장한다(구현 때 결정).

## 초기 설정 (관리자, 한 번)

1. **하드 연결**: 하드를 Seafile 서버 PC(Windows 호스트)에 연결한다. Hyper-V의 Ubuntu에 넘기지 않는다. USB라면 3.0 이상이어야 한다(2.0은 약 35MB/s에서 막힘). 드라이브 문자(예: `E:`)를 확인한다.
2. **사용자 추가**: Seafile 관리자 페이지에서 사용자 "디자인나스"를 만든다. 파일을 올리지 않으므로 할당량은 상관없다.
3. **앱 설치·로그인**: 서버 PC에 Drive 앱을 깔고 디자인나스로 로그인한다. "자동 로그인"을 체크한다. 서버 PC를 다시 켰을 때 로그인 화면에서 멈추지 않게 하기 위해서다.
4. **NAS로 열기**: 설정 → NAS로 열기 → 하드 폴더(`E:\` 또는 그 안의 폴더)를 고른다. 확인 창에서 크기와 파일 수를 미리 세지 않는다(3TB는 세는 데 몇 분 걸린다). 연 뒤 설정 화면에 "검색 색인 N개 만드는 중…"으로 진행을 보여 준다. 자동 실행과 트레이 실행이 꺼져 있으면 함께 켜는 체크박스를 둔다(기본 체크).
5. **방화벽 허용**: 처음 열 때 Windows 방화벽 창이 뜨면 "개인 네트워크"를 허용한다.
6. **색인 만들기**: 앱이 하드 전체를 훑어 검색 색인을 만든다. 설정 화면에 진행 상황(훑은 파일 수)을 보여 준다. 그동안에도 탐색과 내려받기는 된다. 검색은 색인이 끝난 뒤부터 된다.
7. **확인**: 디자이너 PC에서 Drive 앱을 열어 사이드바에 "디자인나스"가 뜨는지, 파일을 하나 내려받아 본다.

그 뒤로는 손댈 것이 없다. 서버 PC를 다시 켜면 앱이 자동 실행·자동 로그인되고, NAS로 열기 설정을 기억해 다시 연다. 열어 둔 상태는 설정 화면에서 끌 수 있다.

## 실제로 켜기 전에 확인할 것

1. **실제 파일 수**: 제공 PC에서 `(Get-ChildItem <하드> -Recurse -File).Count`를 돌려 본다. 색인 크기와 메모리 사용량을 이 숫자로 판단한다.
2. **방화벽**: 제공 PC의 Windows 방화벽이 Drive 앱의 들어오는 연결을 허용해야 한다. 처음 열 때 Windows가 묻는 창에서 "개인 네트워크"를 허용하면 되는지 확인한다.
3. **같은 네트워크인지**: 확인됨. 디자이너 PC와 제공 PC는 같은 사무실 네트워크(같은 서브넷)에 있다. 다른 서브넷이 생기면 mDNS로 찾지 못하므로 제공 PC 주소를 직접 넣는 방법이 필요하다.
