# 공용 NAS 하드를 Drive 앱에서 탐색하기

> 상태: 방향만 정해 둔 초안. 아직 구현하지 않는다. 시작하기 전에 아래 "구현 전에 정할 것"부터 확인한다.

## 왜 만드나

디자인팀이 예전에 쓰던 공용 NAS 하드(4TB NTFS, 약 3TB 사용 중)에 옛 자료가 남아 있다. 디자이너 PC에는 모두 Drive 앱이 깔려 있으므로, 앱 안에서 이 하드를 탐색하고 검색할 수 있게 한다.

지금 Seafile은 D 드라이브의 Hyper-V Ubuntu에서 Dokploy로 돌고 있고, 쓰는 디스크는 1TB다. 3TB를 Seafile로 옮기려면 디스크가 부족하다. 게다가 Seafile은 외부 디스크를 그 자리에서 보여 주지 못한다(블록 저장소에 다시 넣어야 함). 그래서 하드는 SMB로 공유된 그대로 두고, 앱이 그 공유를 직접 읽게 한다.

## 정한 것 (사용자 결정)

- **B 방식**: 하드를 SMB 공유로 열고, Drive 앱(데스크톱)이 `\\호스트\공유` 경로를 Rust로 직접 읽는다.
- **검색은 빨라야 한다**: 호스트의 작업 스케줄러가 색인 파일을 만들고, 앱은 그 파일만 받아서 검색한다.
- **썸네일은 만들지 않는다**: NAS 항목은 확장자 아이콘만 보여 준다.

## 하지 않는 것

- 썸네일·미리보기 생성(원본을 통째로 읽어야 해서 느림)
- 공유 링크, 휴지통, 파일 히스토리(Seafile 기능이라 NAS에는 없음)
- 웹 버전 지원(브라우저는 SMB를 읽을 수 없음). 웹에서는 NAS 항목을 숨긴다.
- 사무실 밖에서의 접근(SMB를 인터넷에 열지 않는다)
- 내용 검색. 지금 Seafile 검색처럼 이름 검색만 한다.

## 구조

```
[Windows 호스트]
  4TB 하드 ── SMB 공유 \\HOST\design
          └─ 작업 스케줄러(매일 밤) → \\HOST\design\_index.json.gz

[디자이너 PC · Drive 앱]
  사이드바 "공용 NAS" ── NasProvider ── Rust 명령(list_dir 등) ── SMB 경로
  검색 ── _index.json.gz 받기 → 기존 searchEntries로 이름 필터
```

### 1. 호스트 설정 (코드 없음)

- 하드를 Windows 호스트에 직접 연결한다. Ubuntu VM에 넘기지 않는다. USB라면 3.0 이상이어야 한다(2.0은 약 35MB/s에서 막힘).
- 공유 폴더를 만들고 디자인팀 계정에 권한을 준다. 옛 자료라 **읽기 전용 권장**. SMB에는 휴지통이 없어서 실수로 지우면 되살릴 수 없다.

### 2. 색인 파일 (PowerShell 스크립트 + 작업 스케줄러)

- 공유 폴더 전체를 로컬 디스크에서 재귀로 훑는다(`Get-ChildItem -Recurse`). 기존 `Entry` 모양(`name`, `type`, `size`, `mtime`, `path`)으로 JSON을 만들어 gzip으로 압축하고, 공유 루트에 `_index.json.gz`로 저장한다.
- 같은 이름 파일을 덮어쓰는 도중에 앱이 읽지 않도록, 임시 이름으로 쓴 뒤 이름을 바꾼다.
- 매일 밤 한 번 돌린다. 그날 새로 넣은 파일은 다음 날부터 검색된다.
- 스크립트는 레포에 둔다(예: `scripts/nas-index.ps1`).

### 3. 앱: 탐색

- `StorageProvider`([src/storage/StorageProvider.ts](../../../src/storage/StorageProvider.ts))를 구현하는 `NasProvider`를 만든다. 사이드바에서는 라이브러리 하나("공용 NAS", `readOnly: true`)로 보인다.
- 지원하는 기능은 목록 보기와 내려받기다. 업로드·이름 변경·삭제·공유는 읽기 전용이라 꺼진다.
- Rust 쪽([src-tauri/src/localfs.rs](../../../src-tauri/src/localfs.rs))에는 폴더 한 단계 목록을 돌려주는 명령을 추가한다. 내려받기는 파일을 복사하는 명령을 추가한다. `read_local_file`은 크기 제한(`READ_CAP`)이 있어서 큰 PSD에는 쓸 수 없다.
- 읽을 수 있는 경로는 설정된 NAS 루트 아래로 제한한다. `..`이나 다른 경로로 빠져나가지 못하게 막는다(신뢰 경계).

### 4. 앱: 검색

- [useSearchIndex.ts](../../../src/features/search/useSearchIndex.ts)에 NAS 라이브러리를 하나 더 넣는다. NAS는 트리 전체를 훑지 않고 `_index.json.gz`를 받아 압축을 푼다.
- 캐시가 최신인지는 `_index.json.gz`의 수정 시각으로 판단한다. Seafile의 `headCommitId`가 하던 역할이다.
- 파일이 수십만 개면 localStorage(약 5MB)에 들어가지 않는다. 그래서 캐시는 메모리에만 두거나 앱 데이터 폴더의 파일로 저장한다(구현 때 결정).

## 구현 전에 정할 것

1. **실제 파일 수**: 호스트에서 `(Get-ChildItem <하드> -Recurse -File).Count`를 돌려 본다. 색인 크기와 메모리 사용량을 이 숫자로 판단한다.
2. **NAS 경로 설정 방법**: 앱 빌드에 넣을지, 사용자가 처음 한 번 입력할지 정해야 한다.
3. **SMB 인증**: 디자이너 PC가 호스트 공유에 이미 로그인돼 있다고 가정한다(Windows 자격 증명). 로그인돼 있지 않을 때 앱에서 무엇을 보여 줄지 정해야 한다.
4. **디자이너 OS**: macOS가 섞여 있다면 SMB 경로가 `/Volumes/...`로 바뀌고, 미리 Finder에서 마운트해 둬야 한다.
5. **찾은 파일로 하는 일**: 내려받기만 할지, "탐색기에서 열기"나 원본 위치에서 바로 열기도 필요한지 정해야 한다.
6. **폴더별 권한**: 공유 권한을 폴더마다 다르게 준다면, 색인 파일 하나에 모든 이름이 들어 있으므로 권한 없는 폴더의 파일 이름도 검색에 노출된다. 단일 권한으로 운영하면 문제없다.
