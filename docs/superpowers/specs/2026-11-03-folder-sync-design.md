# 폴더 동기화: PC 폴더를 드라이브 폴더로 자동 반영

## 왜 만드나

기획팀처럼 문서 작업이 많은 일부 사용자가 대상이다. 이들은 PC의 특정 폴더에 문서를 저장하는 것으로 일을 끝내고 싶어 한다. 지금은 저장한 뒤 Drive 앱을 열어 직접 올려야 한다.

원하는 모습은 이렇다. PC 폴더를 한 번 연결해 두고 Drive 앱은 켜 두기만 한다. 그러면 그 폴더에서 저장, 수정, 삭제한 결과가 드라이브의 같은 이름 폴더에 알아서 똑같이 맞춰진다.

Seafile 공식 동기화 클라이언트가 같은 일을 하지만, 기획팀에게 프로그램을 따로 깔게 하고 싶지 않다는 것이 사용자의 판단이다. 그래서 Drive 앱 안에서 해결한다.

드라이브는 지금처럼 일반 파일과 폴더가 섞인 공간이다. 그 안에 내가 동기화한 폴더 여러 개가 함께 들어 있는 구조다.

```
내 라이브러리/
├── 회의록.pdf          ← 일반 파일
├── 참고자료/           ← 일반 폴더
├── 기획안 (동기화)     ← PC의 D:\기획안 과 연결
└── 2026 제안서 (동기화) ← PC의 ...\문서\2026 제안서 와 연결
```

## 목표

- PC 폴더 → 드라이브 폴더 **단방향 미러링**. PC가 기준이다.
- PC에서 새로 만들거나 고친 파일은 드라이브에 올린다. 같은 이름이면 덮어쓴다. 이전 버전은 Seafile 파일 히스토리에 남는다.
- PC에서 지운 파일은 드라이브에서도 지운다. 지운 파일은 Seafile 휴지통으로 가서 되살릴 수 있다.
- 하위 폴더 구조도 그대로 따라간다.
- 앱이 꺼져 있던 동안 바뀐 것은 다음에 앱이 켜지고 로그인되면 따라잡는다.
- 연결은 여러 개를 만들 수 있다. 각각 따로 일시정지하거나 해제할 수 있다.
- 데스크톱 앱(Windows, macOS, Linux) 전용이다. 웹 버전에서는 메뉴를 숨긴다.

## 하지 않는 것

- **드라이브 → PC 방향(양방향)**: 충돌 처리, 삭제 판단, 내려받은 파일의 재업로드 방지 때문에 규모와 위험이 2~3배라서 미뤘다. 써 보고 필요해지면 넓힌다. 이번 설계의 기준 상태 기록은 양방향에서도 그대로 쓰도록 만든다.
- **가상 드라이브(OneDrive·SeaDrive 방식, Windows Cloud Files API)**: 탐색기에 드라이브를 통째로 보여 주고 연 파일만 내려받아 PC 용량을 아끼는 방식이다. 용량 절약을 원하는 사용자도 있지만 Windows 전용이고 규모가 이 기능의 몇 배라서 별도 프로젝트로 미뤘다. 이번 기능은 핵심 목적("저장만 하면 다른 사람에게 보인다")을 세 OS 모두에서 해결한다.
- **이름 바꾸기·이동 감지**: PC에서 이름을 바꾸거나 옮기면 "옛 이름 삭제 + 새 이름 업로드"로 처리한다. 문서 폴더라 파일이 작아서 받아들인다.
- **설정 페이지**: 추가는 위쪽 메뉴, 관리는 폴더 우클릭으로 한다.
- **관리자용 권한 설정**: 연결 정보는 그 PC에만 저장된다. 기획팀 PC에서만 켜면 된다.

## 이렇게 되면 실패다

- **동기화 버그로 드라이브 파일이 대량으로 지워진다.** 특히 PC 폴더가 잠깐 안 보일 때(외장 디스크 분리, 네트워크 드라이브 끊김, 폴더 이름 변경) "전부 지워졌다"로 판단하고 드라이브를 비우는 것은 가장 나쁜 실패다.
- 드라이브에서 앱으로 직접 넣은 파일을 동기화가 지운다.
- PC의 원본 파일을 동기화가 건드린다. 이번 범위에서 동기화는 PC 파일을 **읽기만** 한다.
- Word가 저장하는 동안 생기는 임시 파일이나 반쯤 쓰인 파일이 올라간다.
- 동기화를 쓰지 않는 사람의 앱 동작이 달라진다.

## 동작

### 연결 만들기

- 제목줄의 [새 폴더] 아이콘 버튼 옆에 **[동기화 폴더 추가]** 버튼을 둔다(`TitleBar.tsx`). 같은 항목을 파일 메뉴(`MenuBar.tsx`)와 빈 곳 우클릭 메뉴(`BackgroundContextMenu.tsx`)의 "폴더 업로드…" 아래에도 넣는다.
- 누르면 OS 폴더 선택 창이 뜬다. 기존 `pickFolder()`와 같은 방식이고 제목만 다르다.
- 고르면 **지금 보고 있는 드라이브 위치**에 PC 폴더와 같은 이름의 폴더를 만들고 바로 첫 동기화를 시작한다.
- **같은 이름 폴더가 이미 있으면** "기존 폴더에 이어서 연결할까요?"라고 묻는다(사용자 결정). 동기화 해제 뒤 다시 연결, 앱 재설치, PC 교체 때 이어 붙이는 길이다.
  - 이어서 연결하면 기준 상태가 비어 있으므로, 첫 동기화는 PC 파일을 전부 올리기(덮어쓰기)만 하고 드라이브에서는 아무것도 지우지 않는다. 그 뒤부터는 평소 규칙대로 동작한다.
  - 같은 이름이 파일이면 연결하지 않는다.
- **크기 확인 (제 판단)**: 연결하기 전에 PC 폴더의 전체 크기와 파일 수를 계산해 "128GB, 파일 3만 개를 드라이브에 올립니다. 남은 용량 200GB"처럼 보여 주고 확인을 받는다. 계정 할당량이 있고 남은 용량보다 크면 연결하지 않는다(`getAccount()`의 `usage`·`quota`). 파일 히스토리(이전 버전)는 Seafile 할당량에 들어가지 않으므로 따로 알리지 않는다.
- 다음 경우에는 연결하지 않고 이유를 알린다.
  - 고른 PC 폴더가 이미 다른 연결의 PC 폴더이거나, 그 안 또는 바깥을 감싸는 폴더다.
  - 지금 위치가 이미 동기화 폴더 안이다.
  - 읽기 전용 저장소다(새 폴더 버튼과 같은 규칙으로 버튼을 끈다).
  - 암호화 저장소다.
- 연결 정보는 그 PC에만 저장된다. 서버 주소와 계정마다 따로 저장하고, 다른 계정으로 로그인하면 그 계정의 연결만 동작한다.

### 동기화 규칙

**기준 상태.** 연결마다 "동기화가 마지막으로 드라이브에 올린 파일 목록"을 저장한다. 각 항목에는 상대 경로, 크기, 수정 시각이 들어간다. 모든 판단은 PC 현재 상태와 이 기준 상태를 비교해서 한다.

| PC 현재 | 기준 상태 | 할 일 |
|---|---|---|
| 있음 | 없음 | 올린다 |
| 있음 | 있음, 크기나 수정 시각이 다름 | 올린다(덮어쓰기) |
| 있음 | 있음, 같음 | 없음 |
| 없음 | 있음 | 드라이브에서 지운다 |

- **동기화는 기준 상태에 있는 파일만 지운다.** 드라이브에서 앱으로 직접 넣은 파일은 기준 상태에 없으므로 남는다. 사용자가 원한 "완전히 똑같이"에서 이 경우만 예외다.
- PC에서 폴더를 지우면 그 안의 기준 상태 파일들을 지운다. 그 뒤 드라이브 폴더가 비어 있으면 폴더도 지운다. 비어 있지 않으면(직접 넣은 파일이 있으면) 남긴다.
- PC의 빈 폴더도 드라이브에 만든다. 기존 `list_upload_files`는 빈 폴더를 돌려주지 않으므로 보완해야 한다.
- 업로드가 성공한 항목만 기준 상태에 반영한다. 실패하면 다음 확인 때 다시 시도한다.
- 드라이브 파일이 다른 경로로 바뀌어 있어도(사용자가 앱에서 덮어씀 등) 확인하지 않는다. PC가 바뀌지 않았으면 다시 올리지 않는다.

**올리지 않는 파일.** Office 잠금 파일(`~$*`), 임시 파일(`*.tmp`, `~*.tmp`), `Thumbs.db`, `desktop.ini`, `.DS_Store`, 그리고 `.`으로 시작하는 숨김 파일과 폴더. 이 목록은 코드 상수로 두고 사용자가 바꾸게 하지 않는다.

**쓰는 중인 파일.** 수정 시각이 몇 초 안쪽이거나 읽기에 실패하면(잠김) 이번 확인에서 건너뛰고 다음 확인 때 올린다.

**변경 감지 (사용자 결정).** Seafile Client와 같은 방식이다. **OS 파일 변경 알림**을 기본으로 쓰고, 전체 비교로 빈틈을 메운다.
- **변경 알림**: Rust `notify` 크레이트로 연결된 PC 폴더를 하위 폴더까지 감시한다. Windows는 ReadDirectoryChangesW, macOS는 FSEvents, Linux는 inotify를 쓴다. 알림이 오면 1~2초 기다려서 모은 뒤(Word 저장처럼 연달아 오는 변경을 한 번에) 그 연결을 비교한다. 저장 후 몇 초 안에 드라이브에 보이는 것이 목표다.
- **전체 비교**: 앱이 켜지고 로그인됐을 때, 연결을 만들거나 다시 시작했을 때, 그리고 **1시간마다** 연결마다 폴더 전체를 훑어 기준 상태와 비교한다. 앱이 꺼져 있던 동안의 변경과 알림이 빠진 경우(버퍼 넘침, 네트워크 드라이브처럼 알림이 오지 않는 폴더)를 잡는다.
- 알림은 "다시 비교하라"는 신호로만 쓴다. 무엇을 올리고 지울지는 항상 PC 현재 상태와 기준 상태의 비교로 정한다. 알림 내용(어떤 파일이 어떻게 바뀌었는지)을 믿지 않으므로 알림 순서가 뒤섞이거나 합쳐져도 결과가 같다.
- 감시를 시작하지 못하면(폴더 없음, 권한 없음) 그 연결은 "PC 폴더를 찾을 수 없음"과 같이 다룬다.

**연결할 수 있는 PC 폴더.** 내장 디스크뿐 아니라 D: 같은 추가 하드, 외장 하드, USB의 폴더도 연결할 수 있다. 디스크를 뽑으면 아래 안전장치대로 멈췄다가 다시 꽂으면 이어서 한다. 네트워크 드라이브(공유 폴더)는 막지 않지만 변경 알림이 오지 않을 수 있어 1시간마다 전체 비교에만 의존할 수 있다. 연결할 때 그렇다고 안내한다.

### 안전장치

- **PC 폴더가 없거나 읽을 수 없으면** 그 연결을 "PC 폴더를 찾을 수 없음" 오류로 멈춘다. 이때 아무것도 지우지 않는다. 폴더가 다시 보이면 이어서 한다.
- **한 번에 지울 파일이 많으면** 멈추고 사용자에게 확인을 받는다. 기준은 **"기준 상태의 절반 이상이면서 10개 이상" 또는 "500개 초과"**다(제 판단). 500개는 Seafile Client의 기본값이고, 문서 폴더는 파일이 적어서 비율 기준을 함께 둔다. 확인 창에는 지울 개수와 PC 경로를 보여 준다.
  - [취소]하면 그 연결을 "확인 필요" 상태로 멈춘다. 사용자가 다시 시작할 때까지 아무것도 지우지 않는다. 다시 시작하면 같은 확인을 다시 거친다(제 판단).
  - 창이 트레이에 숨어 있을 때는 확인 창을 띄우지 않고 "확인 필요" 상태로 멈춘다. 동기화 표시와 상태 표시줄로 알리고, 창이 다시 보이면 확인 창을 띄운다. OS 알림은 이번 범위에서 쓰지 않는다(제 판단).
- **업로드 패널에서 동기화 항목을 취소하면** 이번만 건너뛴다. 기준 상태에 반영되지 않으므로 다음 확인 때 다시 올라간다. 제외 목록은 만들지 않는다(제 판단).
- **OneDrive "필요 시 다운로드" 폴더**도 막지 않는다. 훑기 중 읽기에 실패한 파일은 "쓰는 중인 파일"과 같이 건너뛰고 다시 시도한다(제 판단).
- **이 PC의 앱 안에서 동기화 폴더 자체의 이름을 바꾸거나 옮기면** 연결이 새 경로를 따라간다. 이름 변경·이동 처리 코드에서 연결의 드라이브 경로를 함께 바꾼다(제 판단). 상위 폴더를 바꾼 경우도 포함한다.
- **그 밖의 이유로 드라이브 쪽 연결 폴더가 없어지면**(삭제, 다른 PC나 웹에서 이름 변경) 그 연결을 "드라이브 폴더를 찾을 수 없음" 오류로 멈춘다. 새로 만들어 다시 올리지 않는다.
- 로그아웃하거나 토큰이 만료되면 모든 동기화를 멈춘다. 다시 로그인하면 이어서 한다.
- 동기화는 PC 파일을 읽기만 한다. 쓰기, 삭제, 이동은 하지 않는다.

### 동기화 폴더 안은 읽기 전용 (사용자 결정)

동기화 폴더와 그 하위 폴더 안은 PC가 기준이라 앱에서 읽기만 한다. 읽기 전용 저장소와 같은 규칙이다.

- 업로드, 끌어다 놓기, 새 폴더 만들기, 이름 바꾸기, 삭제, 끌어서 옮기기를 끈다. 내려받기, 공유, 미리보기는 된다.
- 상태 표시줄에 "동기화 폴더 · 읽기 전용"을 보여 준다.
- 밖에서 동기화 폴더 안으로 옮기려 하면 막고 알린다. "동기화 폴더 안은 PC에서만 바꿀 수 있습니다. PC 폴더에서 바꾸면 드라이브에 반영됩니다." [확인]
- 동기화 폴더 **자체**는 부모 폴더에서 이름 바꾸기·옮기기를 할 수 있다(연결이 따라간다). 삭제하려 하면 확인 창을 띄운다. "동기화 연결이 끊깁니다. 연결만 해제하려면 우클릭 → 동기화 해제를 쓰세요." [취소] [삭제]
- 연결을 만든 그 PC에서만 막힌다. 연결 정보가 PC에만 있으니 다른 PC나 웹에서는 일반 폴더로 보인다. 이것은 받아들인다.

### 관리하기

동기화 폴더(연결된 드라이브 폴더)를 우클릭하면 기존 메뉴에 아래 항목이 더해진다.
- **PC 폴더 열기**: OS 탐색기로 연다.
- **지금 동기화**: 주기를 기다리지 않고 바로 확인한다.
- **일시정지 / 다시 시작**
- **동기화 해제**: 연결과 기준 상태만 지운다. 드라이브 폴더와 파일은 그대로 남아 일반 폴더가 된다. `useConfirm` 같은 확인 창을 거친다.

### 표시

- **아이콘**: 동기화 폴더의 폴더 아이콘에 작은 동기화 표시를 겹친다. 목록 보기, 아이콘 보기, 사이드바(트리에 보이는 경우)에 모두 적용한다. 오류 상태면 표시 색을 바꾼다.
- **상세 패널**: PC 경로, 상태(동기화됨 / 올리는 중 n개 / 일시정지 / 오류 문구), 마지막 동기화 시각.
- **상태 표시줄**: 동기화 작업이 있으면 "동기화 중 n개", 오류가 있으면 "동기화 오류 1건"을 짧게 보여 준다. 누르면 해당 폴더로 이동한다.
- **업로드 패널**: 동기화 업로드도 기존 업로드 큐로 보내므로 업로드 패널에 함께 보인다. 사용자가 올린 것과 구분할 필요는 없다(제 판단).

### 앱을 켜 두기

연결을 처음 만들 때 자동 실행이나 "창을 닫아도 트레이에서 계속 실행"이 꺼져 있으면 한 번 안내한다. "앱이 켜져 있을 때만 동기화됩니다. 자동 실행과 트레이 실행을 켤까요?" [켜기]를 누르면 두 설정을 켠다.

**자동 로그인.** 로그인할 때 "자동 로그인"을 체크하지 않았으면 토큰이 이번 실행 동안만 남는다(`session.ts`). 그러면 재부팅 뒤 앱이 로그인 화면에서 멈추고 동기화도 돌지 않는다. 연결을 만들 때 자동 로그인이 꺼져 있으면 위 안내에 "자동 로그인이 꺼져 있어 PC를 다시 켜면 동기화가 멈춥니다"를 함께 보여 주고, [켜기]를 누르면 지금 토큰을 영구 저장으로 옮긴다.

## 구조 (빌더 참고)

- **업로드**: 기존 `UploadQueue`에 `PathFile` 작업으로 넣는다. 덮어쓰기(`replace=1`), 큰 파일 조각 업로드, 이어 올리기를 그대로 쓴다. 하위 폴더는 `relativePath`로 넘긴다(`localUpload.ts`의 `toLocalTasks`).
- **변경 감시**: Rust에 `notify` 크레이트를 추가한다(새 의존성, 사용자 승인). 연결마다 감시를 시작·중지하는 명령과, 변경이 모이면 연결 id를 담아 WebView로 보내는 이벤트를 둔다. 1~2초 모으기(디바운스)도 Rust에서 한다.
- **PC 폴더 훑기**: Rust의 `list_upload_files`(`localfs.rs`)를 재사용하거나 비슷한 명령을 만든다. 빈 폴더를 포함해야 하고, 숨김·임시 파일 제외는 Rust나 JS 중 한 곳에서 한다.
- **비교 로직**: "PC 현재 + 기준 상태 → 할 일 목록"을 순수 함수로 두고 단위 테스트를 단다. 안전장치(대량 삭제 멈춤, 폴더 없음)도 이 함수에서 판단한다.
- **동기화 엔진 위치**: 로그인된 화면 안, `UploadQueueRoot` 아래의 화면 없는 컴포넌트다. MCP 처리 컴포넌트와 같은 방식이다.
- **연결·기준 상태 저장**: PC 로컬에 저장한다. localStorage 또는 앱 데이터 폴더의 JSON 파일 중 빌더가 정한다. 연결 키는 서버 주소 + 계정 + 저장소 id + 드라이브 경로다.
- **드라이브 폴더 식별**: 경로로 식별한다. 앱 밖에서 이름을 바꾸면 "드라이브 폴더를 찾을 수 없음"이 되는 것은 받아들인다.
- **계획 단계에서 먼저 확인할 것**: `--autostart`로 창 없이 켜졌을 때 저장된 세션으로 자동 로그인되고, 숨겨진 WebView에서 동기화 엔진(Rust 이벤트 수신·업로드)이 제대로 도는지. 숨겨진 창에서 타이머가 느려지는 현상이 있다(다운로드 패널에서 관찰됨). 감시는 Rust가 하므로 영향이 적을 것으로 보지만, 1시간 전체 비교 타이머와 업로드 진행은 확인해야 한다.

## 빌더에게 맡기는 것

- 디바운스 시간(1~2초 안에서), "쓰는 중" 판단 기준(초)
- 동기화 아이콘 모양과 색
- 연결 정보 저장 위치(localStorage 또는 파일)
- 확인 창 구현(기존 `Dialog`를 쓸지, `useConfirm`을 새로 들일지)
- 여러 연결을 동시에 돌릴지 차례로 돌릴지
